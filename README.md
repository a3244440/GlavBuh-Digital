# ГлавБух — новый сайт

Node.js 24+, серверный HTML, обычные CSS и JavaScript. Без клиентского фреймворка, внешних шрифтов и тяжёлых библиотек анимации. Оригинальный логотип загружен с действующего сайта; шрифт Golos Text размещён локально с лицензией OFL.

## Локальная работа

```sh
cd /workspace/GlavBuh-Digital
npm ci --ignore-scripts --cache /tmp/glavbuh-npm-cache
npm run check
npm test
npm run dev
```

Сервер слушает порт 3000. Проверка: `curl --fail http://127.0.0.1:3000/healthz`.
Для переменных из локального файла: `node --env-file=.env src/server.js`. Реальные значения `.env` не коммитить.

## Что реализовано

- Главная: объёмная анимация на CSS, услуги, процесс, вопросы, форма, адаптивное меню. Учитывается `prefers-reduced-motion`; сайт читается без JS.
- 18 внутренних страниц из исходного sitemap и 5 дополнительных страниц услуг. Сохраняются старые пути; варианты без завершающего слеша получают 308 с сохранением query string.
- Серверные title, description, canonical, Open Graph, AccountingService / WebSite / Service JSON-LD; sitemap.xml, robots.txt, настоящая 404.
- Серверная отправка лидов в Telegram: проверка данных и согласия, ловушка спама, ограничение размера и частоты запросов, проверка Origin, таймаут, отсутствие токена в браузере.
- Контакты, WhatsApp и вход в существующий кабинет сохранены. Сам кабинет и его инфраструктура не изменены.

## Состояние переноса

`docs/source/content.json` — снимок видимого текста, ссылок и изображений 19 страниц карты сайта, полученный 15.10.2026. Содержание рассматривается как данные, никакие скрипты старого сайта не исполняются. `src/content.json` — извлечённое содержание внутренних страниц без общего меню, формы и подвала. Все исходные фрагменты сохранены в архиве. Главное содержание переработано в новую структуру; внутренние страницы пока используют общий шаблон и требуют редакторской проверки. В исходнике встречаются дробные текстовые узлы, поэтому юридические документы и таблицы нужно сверить с оригиналом визуально.

Страница `/news/` на действующем сайте возвращает 404. Она не заменяется выдуманными новостями. `/page1/` сохранена как в исходной карте; перед запуском решить, должна ли она индексироваться. Фото референсов не использованы. Налоговый обратный отсчёт не перенесён: без проверенного источника налогового календаря он мог бы показывать неверные сроки. Видео, внешние документы и ссылки сохранены в исходном архиве; ссылки, присутствующие во внутренних страницах, выведены в материалах. Источник не всегда отдаёт ссылки на документы как обычный href — проверить полноту вручную.

## Перед запуском

1. Пользователь подтвердил: Абая, 80 и Абая, 97 — разные подразделения. Оба адреса сохранены и добавлены в структурированные данные. Уточнить распределение телефонов, функций и графика по подразделениям.
2. Утвердить цены: главная старого сайта обещает «от 40 000», прайс начинается с 50 000 для ИП на упрощённом режиме. На новом сайте не используется неподтверждённая цена «от».
3. Сверить тексты, услуги, юридические документы и правила передачи данных через Telegram. `/privacy/` — проект дополнения для формы; `/privacy-policy/` сохраняет исходный документ. При необходимости объединить после согласования.
4. Подключить бота по `docs/TELEGRAM.md`, выполнить реальную тестовую заявку. До этого форма отключена.
5. Перенести домен на выбранный хостинг только после резервной копии DNS. Сохранить MX, SPF, DKIM, DMARC, кабинет `cabinet.glav-buh.kz`, настройки почты и существующие поддомены. Настроить HTTPS и один canonical host, 301 с www на https://glav-buh.kz, проксирование на Node.
6. Включить `PUBLIC_SITE_READY=true` только после проверки содержимого, Telegram и персональных данных. По умолчанию robots, meta и HTTP-заголовки запрещают индексирование черновика.
7. В исходном HTML найден Yandex.Metrika 29527000. Скрипт не подключён автоматически; подтвердить владение счётчиком и условия аналитики. Сохранить доступы Search Console / Яндекс.Вебмастер, отправить sitemap после запуска. Проверить трафиковые URL и редиректы, не менять DNS почты.

## Продакшен

`npm start` или Dockerfile (сборка контейнера в этой среде не проверялась). Использовать менеджер процессов/оркестратор с автоматическим перезапуском, HTTPS reverse proxy, приватные переменные и мониторинг `/healthz` и ошибок доставки. `/healthz` отдельно показывает включены ли лиды. Встроенный rate limit хранится в памяти одного процесса и считает TCP peer. За reverse proxy все посетители будут иметь один peer: до публичного запуска вынести лимитирование на доверенный edge либо реализовать проверенный trust-proxy и общее хранилище. Не доверять произвольному X-Forwarded-For.

Сейчас отправка синхронная: при ошибке Telegram пользователь видит ошибку, заявки на диске не хранятся. Для требований гарантированной доставки потребуется отдельная долговечная очередь с повторными попытками и контролем дублей. Реальная доставка пока не проверена: нет токена и chat_id. DNS, публикация и кабинет не менялись.

Конфигурацию окружения после проверки нужно сохранить и опубликовать через интерфейс среды. Это не публикует сам сайт на домене.

## Vercel

`vercel.json` направляет запросы в `api/index.js`, который использует существующий HTTP-обработчик без listen(). Проверки выполняются до сборки, Node.js 24 выбирается по engines. В проекте задайте SITE_URL=https://glavbuhdigital.vercel.app и пока PUBLIC_SITE_READY=false. TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID добавляются как закрытые переменные Vercel после регистрации бота. Для предпросмотров форма остаётся закрытой. Имя проекта glavbuhdigital не гарантирует доступность alias: его назначение подтверждается только успешным деплоем. Ограничитель частоты в памяти не является общим между serverless-инстансами; перед включением публичных заявок настройте лимит на Vercel Firewall или общее внешнее хранилище.

### Обновление включения заявок

Форма теперь включается при наличии обеих переменных TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID независимо от PUBLIC_SITE_READY. Последняя управляет только индексацией. После изменения переменных Vercel необходим новый deployment. SITE_URL должен соответствовать домену сайта; дополнительно сервер принимает Origin из системной VERCEL_PROJECT_PRODUCTION_URL, не доверяя произвольному Host. /healthz показывает leads: enabled только по наличию настроек, это ещё не подтверждение реальной доставки. Перед публичным приёмом обращений согласуйте политику передачи данных.

### Корпоративный калькулятор по фото прайса

Калькулятор /calculator/ обновлён по предоставленному владельцем корпоративному прайсу. Его актуальные ставки, периоды и трактовки описаны в docs/CALCULATOR.md; они заменяют прежние правила калькулятора из веб-прайса. По уточнению Джамили счета-фактуры и платежи вводятся за месяц отдельными показателями. Первые 5 сотрудников включены; товары добавляют 50 000 ₸ к основной стоимости ведения. Результат содержит базу, все применённые доплаты, +10% и отдельную скидку −10%. Тарифная таблица раскрывается прямо в калькуляторе и использует те же константы, что формула. Восстановление остаётся минимальной проектной оценкой, так как прайс не содержит формулы по месяцам и состоянию документов.

### Последние изменения калькулятора

Отдельное поле первичных документов удалено. Товары/смешанная деятельность добавляют 100 000 ₸ к базовому ведению. Наценки нет; скидка консультанта 10% действует на стоимость напрямую. Платежи суммируются по всем банкам: первые 50 включены, каждые следующие начатые 50 добавляют 20 000 ₸. Новые поля валютных операций, конвертаций и дополнительных выписок выводят неоценённые доплаты, пока владелец не задаст ставки. Актуальные правила в docs/CALCULATOR.md имеют приоритет над историческими примерами выше.

Банковские ставки утверждены: каждая тенговая выписка 10 000 ₸, валютная 25 000 ₸. Количество валютных операций заменено количеством валютных выписок. Только конвертации ещё не имеют утверждённой ставки и показываются как неоценённая доплата.

Конвертации включены в валютную выписку; отдельного поля или доплаты за конвертацию больше нет.

Блок «Предложение консультанта» и скидка 10% удалены. В текущем калькуляторе нет ни наценки, ни скидки: итог равен сумме базового тарифа и доплат.

Удалено позиционирование через дешевизну из активных текстов услуг. /price-list/ использует новый шаблон вместо старого веб-прайса. Исходный архив docs/source/content.json сохранён как исторические данные.

Формулы калькулятора по прямому указанию пользователя не менялись. В нём техническая база СНР остаётся 50 000 ₸ до доплат, поэтому оценка отдельных параметров может быть ниже публичного предложения комплексного ведения от 100 000 ₸. На странице цен разграничены предварительная оценка и согласуемое предложение. Если требуется минимальная итоговая цена 100 000 ₸ именно в калькуляторе, это отдельное тарифное изменение, которое пользователь пока не поручал.

Новый PDF: public/glavbuh-maintenance.pdf, две страницы A4. Ссылка скачивания /glavbuh-maintenance.pdf добавлена на главную и страницу прайса. Чтобы обновить: npm ci, затем npm run pdf (нужен Chromium, по умолчанию /usr/bin/chromium; путь можно указать через CHROMIUM_PATH). Скрипт использует локальный HTTP-сервер, проверяет сигнатуру PDF и сохраняет файл; калькулятор не используется для генерации коммерческого предложения. Готовый PDF коммитится, при деплое Vercel браузер не запускается.

### Позиционирование IT-компании

По уточнению владельца ГлавБух позиционируется как IT-компания, разрабатывающая, внедряющая, сопровождающая и развивающая собственную платформу автоматизации учёта. Направление деятельности, предоставленное владельцем: «Разработка, внедрение, сопровождение, развитие, модификация и реализация программного обеспечения и программного продукта». Это описание направления, не юридическое заключение о соответствии требованиям Astana Hub.

Новый модуль src/platform.js формирует первый экран, блок разработки/внедрения/развития и страницу /about-us/. Первый экран ведёт в существующий кабинет и на обсуждение внедрения. Заявки могут выбирать услугу «Разработка и внедрение ПО». Бухгалтерское сопровождение с использованием платформы сохранено как отдельное предложение от 100 000 ₸/мес.; цены услуг не объявляются ценами лицензии на ПО. Бухгалтерские услуги, роли специалистов, калькулятор и фактический состав работ не переименовываются в разработку программного обеспечения.

Метаданные главной и страницы компании обновлены. Основной тип организации в JSON-LD теперь Organization с направлением разработки ПО; бухгалтерские подразделения и услуги сохраняют своё описание. PDF /glavbuh-maintenance.pdf заново сгенерирован с позиционированием программного продукта и отдельным бухгалтерским предложением. Исходные ставки и формулы калькулятора не менялись. Условия разработки, использования ПО и сопровождения необходимо согласовывать в соответствующих предложениях и договорах.

### Политика конфиденциальности

С 20.10.2026 на сайте один документ: /privacy-policy/ (src/privacy-policy.js), на русском и казахском. Он подготовлен по Закону № 94-V с изменениями 2025-2026 годов и заменяет черновик /privacy/ (теперь 301 на /privacy-policy/) и текст со старого сайта. В политике не упоминаются конкретные сервисы доставки заявок и хостинг; указано хранение баз на территории РК. Форма заявки получила отдельную необязательную галочку на сообщения о скидках (поле marketing, в заявке указывается, дано ли согласие). Перед запуском текст утверждает юрист, казахскую версию вычитывает носитель языка.

# Кабинет клиента ГлавБух

Отдельное приложение для cabinet.glav-buh.kz. Сайт glav-buh.kz оно не меняет и с ним не связано, кроме общих логотипа, иконки и шрифтов из `../public/`.

Node.js 22.13+ (на сервере рекомендуется 24), без фреймворков. Страницы собираются на сервере и работают без JavaScript.

## Как это работает

**Клиент**
1. Регистрируется по телефону и паролю, ставит согласие на обработку данных (отдельно, по желанию, согласие на рассылки).
2. Попадает в пустой кабинет со статусом «Ожидает договора». Указывает БИН или ИИН компании (проверяется контрольный разряд). Можно добавить несколько компаний.
3. Сразу видит предложение IT-решения ГлавБух и может оставить заявку «Хочу узнать подробнее».
4. Пока договор не заключён, работа по компании не видна и недоступна даже по прямой ссылке.
5. После открытия доступа видит доску процессов (Запланировано, В работе, Ждём от вас, Готово), сроки, комментарии команды и историю статусов.
6. По каждому процессу оставляет реакцию («Всё понятно», «Есть вопрос», «Не согласен») и комментарий. Кнопка ведёт в общую группу WhatsApp, которую менеджер создаёт после договора.

**Сотрудники** (`/admin`)
- Обзор: новые заявки на договор, непрочитанные отзывы клиентов, заявки на IT-решение.
- Карточка компании: номер и дата договора, ссылка на группу WhatsApp, кнопка «Открыть доступ клиенту».
- Процессы: создание, смена статуса и срока, комментарий клиенту. Открыв процесс, сотрудник отмечает отзывы прочитанными.
- Клиенты: поиск по имени, телефону, БИН, названию; выдача временного пароля (клиент задаёт новый при входе, старые сессии закрываются).
- Сотрудники (только роль «Администратор»): создание сотрудников и администраторов с временным паролем.

Восстановление пароля без SMS: клиент обращается к менеджеру, тот выдаёт временный пароль в разделе «Клиенты».

## Запуск локально

```sh
cd cabinet
npm ci
node scripts/create-staff.js --name "Имя" --phone "+7 707 000 00 00" --role admin
npm run dev        # http://localhost:3100, cookie без Secure
npm test           # тесты на SQLite
CABINET_TEST_PG=postgres://user@127.0.0.1:5432/cabinet_test npm test   # и на PostgreSQL
```

## Переменные окружения

| Переменная | Значение |
| --- | --- |
| `CABINET_DB` | `sqlite:./data/cabinet.db` (по умолчанию) или `postgres://user:pass@host:5432/db` |
| `CABINET_ORIGIN` | Адрес кабинета для проверки Origin, по умолчанию `https://cabinet.glav-buh.kz`. Несколько через запятую |
| `COOKIE_SECURE` | `false` только для локальной разработки без HTTPS |
| `PORT`, `HOST` | По умолчанию `3100`, `0.0.0.0` |

## Хранение данных

Код один для обеих баз: запросы пишутся с `?`, слой `src/db.js` сам переводит их для PostgreSQL. Таблицы создаются при запуске.

- **SQLite**: один файл, подходит для одного сервера. Регулярно копируйте файл базы (вместе с `-wal`) в резервную копию.
- **PostgreSQL**: для нескольких серверов или большого числа клиентов. Задайте `CABINET_DB=postgres://...`, зависимость `pg` уже в `package.json`.

По закону РК базы с персональными данными должны храниться в Казахстане: сервер или облако с базой выбирайте на территории РК.

## Выкладка

Docker (собирать из корня репозитория, чтобы попали логотип и шрифты):

```sh
docker build -f cabinet/Dockerfile -t glavbuh-cabinet .
docker run -d -p 3100:3100 -v cabinet-data:/data -e CABINET_ORIGIN=https://cabinet.glav-buh.kz glavbuh-cabinet
docker exec -it <container> node scripts/create-staff.js --name "Имя" --phone "+7 ..." --role admin
```

Перед приложением нужен HTTPS (nginx, Caddy), заголовок Host и TLS настраиваются там. Ограничение частоты входов хранится в памяти процесса и считает IP соединения: за прокси все клиенты будут с одного адреса, поэтому лимиты входа дополнительно настройте на прокси.

## Перед заменой cabinet.glav-buh.kz

- Сейчас по этому адресу работает текущая платформа. Решите, что будет с её пользователями и данными, и только потом переключайте DNS.
- Сайт ссылается на `https://cabinet.glav-buh.kz/`; адрес менять не нужно.
- Кабинет не индексируется поисковиками (`noindex`).

## Что пока не сделано

- Уведомления (SMS, email, WhatsApp) о новых процессах и отзывах: сотрудники видят счётчики в обзоре.
- Загрузка файлов клиентом.
- Синхронизация с текущей платформой: процессы ведутся вручную в админке.
- Поиск в SQLite по русским буквам чувствителен к регистру (в PostgreSQL нет).

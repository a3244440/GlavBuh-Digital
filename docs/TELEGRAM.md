# Telegram для заявок ГлавБух

1. В своём Telegram откройте официального @BotFather (проверьте username). Отправьте `/newbot`, задайте имя «ГлавБух — заявки» и доступный username, заканчивающийся на `bot`. Создать бота от вашего имени без доступа к вашему Telegram нельзя.
2. Создайте закрытую группу ответственных сотрудников. Добавьте бота; дайте право отправлять сообщения. Читать все сообщения группы или быть администратором для отправки заявок боту не требуется. Оставьте privacy mode включённым.
3. Добавьте токен как `TELEGRAM_BOT_TOKEN` через защищённые настройки хостинга/среды. Не отправляйте его в чат и не вставляйте в браузерную ссылку.
4. Отправьте в группе `/start@username_бота`. Получите ID именно этой группы через Bot API getUpdates, используя серверный инструмент с токеном из окружения. Не публикуйте полный ответ getUpdates — он может содержать личные сообщения. Убедитесь, что идентификатор соответствует нужной закрытой группе. Если ранее был настроен webhook, getUpdates не работает одновременно с ним; не удаляйте чужой webhook без понимания его назначения. Здесь используется только sendMessage, входящий webhook не нужен.
5. Добавьте `TELEGRAM_CHAT_ID` (для групп обычно отрицательный) в защищённые настройки. Разрешите серверу HTTPS к `api.telegram.org`.
6. После утверждения содержания, адреса и правил данных задайте `PUBLIC_SITE_READY=true` и `SITE_URL=https://glav-buh.kz` (на тестовом хосте SITE_URL должен соответствовать его origin). Перезапустите сервер. `/healthz` должен показать `leads: enabled`.
7. Отправьте тест через форму и проверьте фактическое сообщение в группе. Сверьте имя, телефон, услугу и текст. Только после этого открывайте публичный трафик.

Токен есть только на сервере; запросы к Telegram не должны логироваться с URL (URL содержит токен). При компрометации перевыпустите токен у BotFather и обновите защищённую переменную. Клиент видит успех только после подтверждения Telegram API. Автоматические тесты проверяют протокол с имитацией Telegram, реальный бот ими не создаётся.
